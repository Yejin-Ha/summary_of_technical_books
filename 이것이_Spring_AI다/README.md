# 01. Spring AI 시작
- 자바와 파이선에는 AI 모델을 구현하기 위한 프레임워크가 존재하며 파이선은 랭체인(LangChain), 자바는 Spring AI이다.



# 02. 텍스트 대화
chat model을 사용한다. 
- ChatModel 인터페이스 : 텍스트 기반 대화형 인터페이스. 입력된 프롬프트를 LLM에게 동기 요청을 보내며 완전한 응답을 받은 뒤 String/ChatResponse로 반환한다
    - StreamingChatModel 인터페이스 : 프롬프트를 LLM에게 비동기 요청을 보낸 뒤 텍스트 응답을 받으면 Flux<String> / Flux<ChatResponse> 로 반환한다.
    청크 단위로 순차적으로 사용하는 Flux 형태이기 때문에 메모리 사용량이 줄어들며 대규모 동시성 처리가 가능하여 실시간 채팅, 로그 스트리밍 등에 핵심 역할을 한다.
    - prompt 클래스 : 복수 개의 시스템 메시지, 사용자 메시지, AI 메시지를 저장한다.
    - ChatOption 인터페이스 : Start-up 옵션, runtime 옵션 등 대화 옵션이 존재한다.

- 사용자의 질문이 LLLM에서 처리하기 힘든 경우 도구 호출을 요청하는데 애플리케이션과 LLM 간의 복잡한 대화 흐름이 발생하고 이 흐름은 ChatClient가 관리한다.


# 03. 프롬프트 엔지니어링
- 프롬프트 : 대규모 언어 모델(LLM)에게 원하는 작업을 구체적으로 지시하거나 질문의 형태로 요구사항을 전달하는 일종의 명령문
- Spring AI에서는 Prompt 클래스를 사용하며 해당 클래스에는 메시지들과 대화 옵션을 담고 있다.
    - 대화 옵션은 ChatOptions와 동일하다.
    - 메시지 
        |메시지 타입|설명|
        |---|---|
        |SystemMessage|LLM의 행동과 응답 스타일을 지시하는 메시지|
        |UserMessage|사용자의 질문, 명령을 담고 있는 메시지|
        |AssistantMessage|LLM의 응답 메시지로 답변 전달을 넘어 대화 기억 유지에도 사용됨|
        - UserMessage만 포함된 경우는 존재하지만 UserMessage 없이 SystemMessage 나 AssistantMessage만 포함된 경우는 없다. UserMessage는 필수로 포함되어야 한다.
        - 여러 대화를 기억하고 응답할 경우엔 다수의 UserMessage를 입력하고 각 경우에 AssistantMessage에 프롬프트 진행 이력을 저장하여 사용한다.
- 기본 메시지와 옵션 설정하기
    - ChatClient.Builder 내부에 기본 설정을 위한 메소드가 존재한다.
        - defaultSystem(), defaultUser(), defaultOptions()
- 프롬프트 엔지니어링
    1. 제로-샷 프롬프트
        - 예시 없이 작업을 수행하도록 요청하는 방법
    2. 퓨-샷 프롬프트
        - 몇 개의 예시를 제공하여 사용자가 원하는 방식으로 출력하도록 유도하는 기법. 한 개의 예시를 제공하는 것을 원-샷 프롬프트라고 한다.
    3. 역할 부여 프롬프트 
        - 특정 정체성, 전문성 또는 관점을 부여함으로써 출력 내용의 스타일, 톤, 깊이를 조정할 수 있다.
    4. 스탭-백 프롬프트 
        - 질문을 여러 단계로 분해해, 단계별로 배경 지식을 확보하는 기법
            > ex) 서울에서 울릉도 갈 때 비용이 가장 적게 드는 방법은?
            >
            > [1단계] 서울에서 울릉도 가는 교통 수단은 무었이 있나요? 
            >
            > [2단계] 각 교통 수단의 비용은 얼마인가요?
            >
            > [3단계] 비용이 가장 적은 교통 수단은 무엇인가요?
    5. 생각의 사슬 프롬프트(CoT 프롬프트)
        - 문제를 해결하는 과정을 명시적으로 요청하거나 논리적인 단계로 생각하도록 요구함으로써, 다단계 추론이 필요한 작업에서 성능을 향상시킬 수 있다.
    6. 자기 일관성
        - 여러 번 요청해서 얻은 응답을 집계하여 다수결로 최종 응답을 정하는 기법이다. LLM 출력의 변동성을 해결할 수 있다.

# 04. 구조화된 출력
데이터의 의미와 관계를 고려하여 JSON 같은 형식으로 출력하는 것을 **구조화된 출력**이라고 한다.
Spring AI는 이런 작업을 할 수 있도록 구조화된 출력 변환기 StructuredOutputConverter<T> 인터페이스를 제공한다.
아래 변환기들은 해당 인터페이스를 상속받았다.
- ListOutputConverter : List<String> 으로 변환
- BeanOutputConverter : T(객체)로 변환
- MapOutputConverter : Map으로 변환

# 05. 음성 대화
- SST(Speech-to-text) : 사람이 말한 음성을 텍스트로 변환하는 기술이다.
- TTS(text-to-speech) : 텍스트 문자을 자연스러운 음성으로 변환하는 기술이다.

Java에서는 OpenAI 스타터 패키지에서 `OpenAiAudioTranscriptionModel`, `OpenAiAudioSpeechModel`를 사용할 수 있다.


# 06. 비전 및 이미지 생성
* 컴퓨터 비전 : 기계가 주변 세계를 **보고** 해석하도록 만드는 기술
    - ex. 자율주행, 안면 인식, 의료 영상 분석, 보안 시스템, 제조 시스템, 스마트폰 카메라
* MultiModal : 텍스트, 이미지, 오디오, 비디오 등 다양한 형태의 데이터를 동시에 입력받고 통합적으로 처리할 수 있는 AI 모델의 능력
    - LLM을 활용하여 개발을 할 때 LLM이 어디까지 비전 기능을 지원하는지 정확히 알고 있어야 한다. 
* 객체 탐지 : 이미지나 영상 속에서 어떤 객체가 어디에 위치해 있는지를 찾아내는 기술로 AI가 시각적 정보를 이해하기 위해 기본적으로 수행하는 작업 중 하나이다.
    - 단순히 객체의 존재 유뮤 파악을 넘어 객체의 종류, 위치(좌표)를 제공한다.
    - 딥러닝 모델 예시 : YOLO, SSD, Faster R-CNN 등
* 이미지 생성형 모델 : 텍스트 프롬프트를 바탕으로 새로운 이미지를 자동으로 만들어주는 모델. 딥러닝 기반의 확산 모델 아키텍처를 가지고 수백만 장 이상의 이미지와 그에 대응하는 설명 텍스트로 학습되었다.
    - 확산 모델 아키텍처는 원본 이미지를 Diffusion 과정을 거쳐 노이즈 이미지를 만들고, 반대로 노이즈가 가득한 이미지를 Denoising 과정을 거쳐 원본 이미지로 재생성하는 구조로 되어있다.
* text-to-image : 프롬프트가 입력되면 모델은 이를 해석하고 시각적인 장면을 생성하는 기능. (Spring Image Model API의 기능 중 하나다)
* Spring Image Model API
    - ImageModel 인터페이스를 기반으로 구성된다.
    - ImageModel Interface : ImagePrompt를 매개값으로 받아 이미지 생성 모델에 요청을 보내며 Image Response 객체를 반환한다.
    - ImagePrompt Class : ImageMessage와 ImageOptions를 입력받아 이미지 생성형 모델의 입력된 데이터를 캡슐화한다.
    - ImageMessage Class : 이미지 생성에 사용할 텍스트와 해당 텍스트가 이미지 생성에 미치는 영향력을 나타내는 가중치를 캡슐화한다.
    - ImageOptions Interface : 이미지 생성 모델의 옵션을 설정한다.(ex. 사용할 모델 이름, 이미지 폭과 넓이, 이미지 생성 개수, 결과 형태 등)


# 07. 모델 전,후처리 어드바이저
advisor : Spring 애플리케이션과 LLM간의 상호작용을 가로채어, LLM에게 전달되는 프롬프트를 강화하거나 LLM의 응답을 변환하는 유연하고 강력한 방법을 제공한다. 이는 Interceptor 개념과 유사하다.

Advisor API는 크게 CallAdvisor Interface와 StreamAdvisor Interface로 구분된다.
- CallAdvisor : 동기 방식으로 LLM을 호출할 때 사용
    - CallAdvisorChain으로 관리한다.
    - Spring Web(WebMVC) 기반에서 구현한다.
- StreamAdvisor : 비동기 스트리밍 방식으로 LLM을 호출할 때 사용
    - StreamAdvisorChain으로 관리한다.
    - Spring Reactive Web(WebFlux) 기반에서 구현한다.

Ordered Interface : Advisor Chain 안에서 실행 순서를 결정하는 `getOrder()` 메소드를 제공하며 메소드의 반환되는 숫자가 낮을수록 맨 먼저 전처리를 실행한다.

Advisor 구현시 재정의해야할 메소드는 다음과 같다
|메소드명|설명|
|---|---|
|`getName()`|Advisor 이름 반환|
|`getOrder()`|Advisor 우선 순서 반환|
|`adviseCall()`|동기 방식의 전처리/후처리 작업|
|`adviseStream()`|비동기 스트림 방식의 전처리/후처리 작업|

- Advisor 적용시 ChatClient 생성시 기본으로 추가하는 방법과 요청마다 추가하는 방법이 있다.


# 08. 임베딩과 벡터 저장소
* 임베딩(embedding) : 텍스트나 이미지 같은 데이터를 부동 소수점 숫자로 이루어진 벡터로 변환하는 과정
* 임베딩 모델 : 임베딩을 수행하는 모델
* 벡터 저장소(Vector store) : 임베딩 모델이 출력한 벡터 데이터를 저장하고, 유사도 검사를 수행하는 특별한 유형의 데이터베이스

벡터화된 데이터는 수학적으로 유사도를 계산하기 쉬워지고 벡터의 방향과 크기가 비슷할수록 해당 데이터 간의 유사도(similarity)가 높다고 판단한다.

이미지 임베딩의 대표적인 사례는 얼굴 인식이며 이미지 임베딩 모델에서 사용되는 신경망 아키텍처는 CNN과 Vit로 나눌 수 있다.
    - CNN(Convolutional Neural Network) : 이미지를 슬라이딩 하면서 지역적인 특징을 추출하는데 중점을 둔다.
    - ViT(Vision Transformer) : 이미지를 일정 크기의 작은 조각(패치)으로 나눈 뒤, 각 패치들이 전체 이미지 내에서 어떤 관계를 갖는지를 학습하는데 중점을 둔다.


# 09. 대화 기억
- 대화 기억(Chat Memory) : 현재 세션에서 LLM과 대화할 때 맥락을 유지하기 위해 사용하는 메시지들. 세션이 종료되면 없어지거나 영구 저장할 수 있다.
    - 대화 기억은 Advisor를 통해 프롬프트에 추가할 수 있다.
- 대화 기록(Chat History) : 과거 세션에서 주고받은 모든 메시지들.
- 대화 기억을 벡터 저장소에 저장하면 현재 대화와 유사한 이전 대화 기록을 검색하여 활요할 수 있다.
    - 대화의 양이 많고 현재 대화와 관련된 기억만 선택하고자 할 때 효과적이다.
    - 텍스트 임베딩과 유사성 검색 과정을 거치므로 다른 방식에 비해 응답 속도가 느리다.


# 10. 문서 검색 기반 답변, RAG
생성형 AI 모델은 사전 학습된 데이터에 기반해 동작하기 때문에 학습 이후의 정보에 대해서는 정확한 답변을 할 수 없거나 실제와 다른 내용을 생성할 수 이따. 이를 해결하기 위해 파인 튜닝, 검색 증강 생성, 도구 호출 등의 기술을 사용할 수 있다.
- 파인 튜닝(fine-tuning) : 기존 모델을 추가 학습시키는 방법. 고성능 하드웨어와 훈련에 필요한 많은 양의 데이터, 훈련 시간이 필요하다.
- 검색 증강 생성(RAG, Retrieval Augmented Generation) : 지식 기반 정장소(벡터 저장소)에 우선 검색 후 검색 결과를 프롬프트 내에 문맥으로 추가해서 프롬프트를 증강하는 방식
- ETL 파이프라인 : Spring AI에서 텍스트를 추출하고 Document로 변환하고, 벡터 저장소로 적재하는 일련의 과정을 말한다.

Document는 텍스트 콘텐츠 외에 메타 데이터를 가질 수 있는데 Spring AI에서는  `DocumentTransformer`를 통해 키워드를 뽑아 메타 데이터로 추가할 수 있다.<br/>
메타데이터가 존재할 경우 필터링을 통해 검색 효율을 높을 수 있다.

RAG용 Advisor는 검색, 증강, 생성 단계를 모듈화한 구조로 되어있으며 필요한 모듈을 조합하여 유연하게 사용할 수 있다.
- 모듈 구분
    |모듈명|설명|
    |---|---|
    |검색 전(Pre-Retrieval) 모듈|유사도 검색 전에 실행하는 모듈|
    |검색(Retreival) 모듈|유사도 검색 시 사용하는 모듈|
    |검색 후(Post-Retrieval) 모듈| 유사도 검색 후 실행하는 모듈|
    |생성(Generation) 모듈|LLM으로 보내기 직전에 실행하는 모듈|
